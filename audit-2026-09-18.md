### ⚠️ Read the performance numbers with this caveat

Part A was measured against a **bare local static server** — no Brotli, no compression, and none of the `_headers` cache rules Cloudflare Pages applies in production. It is **not comparable to the footer's 99 / LCP 1.8s**, which were scored against the deployed site in June 2026.

To get a usable signal I measured the pre-change commit `12a1edc` on the *same* harness, three runs each, and compared medians:

The lone `99` in the BEFORE column is a run-to-run outlier — that run also caught a fast Google Fonts fetch (FCP 1.56s vs 2.9s on its siblings). Both builds sit at ~89–90 on this harness for the same reason: the local server ships uncompressed bytes and the page preloads webfonts over the live network. **Production scores need a re-run against the deployed URL after this ships** — see P1 #2.

### CLS specifically — the thing that was flagged as at-risk

**CLS did not regress.** 0.0036 → 0.0024 (medians), roughly 40× under the 0.1 threshold in both builds.

The `<strong>` elements are not a shift risk here, and the reason is structural: every bold metric sits *inside* an existing `<p>` whose font stack, size and line-height are unchanged. DM Sans 700 is already part of the preloaded font request (`wght@0,400;0,500;0,700`), so the bold weight arrives in the same payload as the regular one — there is no second fetch and no synthesized-bold-to-real-bold reflow. Rendered weight measured at **700** at both the 16px and 17px description sizes.

Page weight dropping 73 KiB also removed two card thumbnails from the critical path, which is why LCP is flat-to-slightly-better even though the featured card and its image moved from the bottom of the strip to the top.

## Manual accessibility pass (the ~60% tools miss)

- **Keyboard operability** — all new interactive elements are real `<a>` elements in DOM order: the featured card's three links, the Collette card's two, and the two inline links in the "Also built" line. No `tabindex`, no click handlers on non-interactive elements. Tab order follows visual reading order at every width tested.
- **Focus Not Obscured (WCAG 2.2)** — the sidebar is `position: sticky` in its own column, not an overlay, and there is no sticky header or banner over the content column. Nothing can cover a focused element.
- **Contrast, computed from tokens** — the new `.also-built` line uses `--color-text-muted #a8a8a2` on `--color-bg #0f0f0e` = **8.03:1** (AA normal text needs 4.5:1). Its links inherit `--color-accent #60c8f0` = **10.06:1**. Body text = 15.59:1.
- **Meaning not by color alone** — bold metrics are conveyed by font weight *and* their literal wording; removing color changes nothing.
- **Alt text** — the Collette thumbnail moved from the Experience entry to the project card carrying its original descriptive alt text intact. The ollae featured image keeps its alt.
- **`prefers-reduced-motion`** — untouched by this change; `main.js` still removes the spotlight entirely under reduced-motion or touch.

## Part B — §1–6 (feedback, destructive actions, errors, forms, AI UX, data safety)

Not applicable, and that is a real answer rather than a skipped section. The homepage is a static document: no async actions, no network calls, no forms, no destructive operations, no user work to lose, and no AI features in the page itself. The only interactive JS is the lightbox in `site/scripts/main.js`, unchanged here, which uses a native `<dialog>` with `showModal()` — Esc-to-close and the focus trap come from the platform, and focus return to the trigger is handled explicitly on `close`. It degrades to a plain link to the full-size image with JS off.
