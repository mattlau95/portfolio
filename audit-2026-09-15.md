**LCP element and `fetchpriority`**
Lighthouse picks the hero `<img>` (`main.case-study > figure.hero-figure > a > img`) as the LCP element on both mobile and desktop. Its LCP-discovery checklist passes all three checks: `fetchpriority=high` applied, request discoverable in the initial document, not lazy-loaded. Network waterfall: the image request starts at 31ms at priority High; the three font files start at 126ms at VeryHigh (after the Google Fonts CSS returns) and are not delayed by the image. LCP breakdown (unthrottled): TTFB 16ms · load delay 11ms · load duration 19ms · **element render delay 101ms** (137ms desktop). The image is not competing with the font preload; the two costs are the 83 KB payload under simulated slow-4G and the render-blocking CSS (style.css 307ms, tokens.css 157ms, by design). Keep `fetchpriority="high"`.

| Tier | Meaning | When to fix |

## Prompt 2 — Code + flow review of `projects/collette.html` (§1–6, §10)

- **§1–6 (status, destructive, errors, forms, AI, data loss):** no async actions, no network calls beyond static assets, no forms, no destructive actions, no AI output. All items N/A. The only JS is `scripts/main.js`: the spotlight (removed under `prefers-reduced-motion` and on touch) and the scroll-spy, which returns early because the page has no `nav a[href^="#"]`.
- **Figure semantics:** hero is `<figure class="hero-figure">` → `<a>` → `<img>` + `<figcaption>`; three body figures are `<figure class="media-figure">` with one `<figcaption>` each; the March 2023 pair is one `<figure>` containing a `.media-pair` grid of two `<img>` and a single shared caption — valid and matches the v6 caption model (one caption per placement). Every `<img>` has descriptive alt, explicit `width`/`height`, and `loading="lazy"` except the hero (`fetchpriority="high"`).
- **Table semantics:** `<table class="token-table">` with `<caption>`, `<thead>` of four `<th scope="col">`, `<code>` on every hex value and code name (mono via the shared table rule). No `scope="row"` on the Value column — it is data, not a row header, and axe/pa11y accept it. Wrapper `.table-wrap` gives `overflow-x: auto` (see P2.1 for the caption consequence).
- **Focus states:** both interactive elements use the global `:focus-visible` ring (`2px solid var(--color-accent)`, offset 2px). Verified computed outline on the hero link: `solid 2px rgb(96, 200, 240)` with `display: block`, so the ring wraps the whole image.
- **Reduced motion:** no new animation or transition was added; `.hero-figure` uses a static `transform: translateX(-50%)` for centering only. Existing `prefers-reduced-motion` handling for spotlight and scroll behaviour applies unchanged.
- **Image sizing / layout shift:** all six `<img>` carry intrinsic `width`/`height`; mobile CLS 0.001 confirms no shift from images. The desktop 0.063 is font-swap reflow (P2.2), not image sizing.
- **Breakout hero:** `width: min(calc(var(--max-width) - 2 * var(--space-8)), calc(100vw - 2 * var(--space-8)))` with `left: 50%; transform: translateX(-50%)`. Because the offset is applied via transform, the pre-transform box does not extend the scrollable area; measured `scrollWidth === clientWidth` at 360, 390, and 1440px. `sizes="(min-width: 1400px) 1336px, calc(100vw - 4rem)"` matches the two rendered cases exactly (1336px at ≥1400; viewport minus 64px below).
- **§10 hierarchy:** one h1, no h2 until the three spoke headings (`text-xl`), body prose in the 65ch column, hero at full shell width. Links are underlined with the accent (`text-decoration-color`). Consistent spacing via tokens. Passes.
